# RGBのみを入力するSmolVLAの初回再学習記録

このページは初回候補V13までの記録。後続のデータ増量実験は [各タスク50件への増量](rgb_only_balanced50.md) を参照。

RGB画像・関節状態・言語指示のみで3タスクを扱うモデルを追加した。
**3タスクすべての成功はまだ確認できていない。** 既存のRGB-Dモデルと公開済みの既定設定は維持している。

## 入力と出力

- 入力画像：正面（一人称）RGB、側面RGB、約0.2秒前の正面RGB。モデル内では256×256に変換。
- 関節状態：左右各6軸の関節角と関節速度、合計24値。
- 言語指示：水滴回収、左腕でのペン把持、両腕でのキャップ装着。
- 出力：両アーム12軸の関節目標。ROS 2の既存軌道コントローラに送信する。

深度カメラはシーンから削除し、深度トピックを購読しない。
モデルの入力辞書はRGBとエンコーダ値に限定する。
物体位置・軸方向の真値、接触判定、教師のフェーズは推論入力に含めない。
RGB版の関節角と速度は同じ画像時刻へ同期する。

## 学習

SmolVLAにLoRAと入出力射影層の追加学習を行った。
キャップ装着の順序を保持する候補では、SmolVLAの特徴に学習可能なGRUのアクション出力層を追加している。
これは既定のSmolVLAに独自の学習済み出力層を加えた構成である。
3タスクで同じモデル重みを使い、タスク別モデルへの切り替えは行わない。

教師はシミュレータ内の物体真値とロボットの逆運動学を用いて関節目標を作る。
真値は教師ラベル作成と評価にだけ使用する。入力画像はRGBのみ。
回復データでは、途中までモデルで動かした状態を教師が引き継いで修正する。
教師による回復成功は、モデル単独の成功として数えない。

最新の出力層の学習は38エピソード・2,602フレーム、検証は別の8エピソード・402フレーム。
旧把持判定で失敗扱いになった3本の教師軌跡は、確認済みの教師動作部分だけを
`supervision.json`で明示して使用した。元の失敗結果は書き換えていない。

画像の特徴と関節状態から、動作段階・関節目標を学習する。
キャップの段階別目標を使う候補では、教師軌跡の終端関節値から目標を学習している。
関節目標の学習損失には既知のロボット運動学も用いるが、
推論時に物体の真値を使って目標を補正する処理はない。

## 評価の扱い

`3300002`は開発用シナリオであり、独立した最終テストではない。
回復データにはこのシナリオの運動条件と、新しい初期位置シードを使った軌跡を含む。
検証エピソードは学習データに混ぜていない。

把持の固定指角度による誤判定を修正し、対象物への両面接触と、
物体に阻まれながら指を閉じる指令で把持を確認する。
旧判定も`legacy_success`として保存する。
キャップ装着の条件は、挿入深さ29〜38mm、横ずれ2mm未満、
軸角度8度未満、軸方向相対速度1.5mm/s未満、0.6秒以上の安定保持を維持した。

## ローカルの実行例

Ubuntu 24.04側で実行する。RGB版の重みはローカルの実験成果物で、まだ公開していない。

```bash
cd ISSRobotArmSim
git switch rgb-only-smolvla
source /opt/ros/jazzy/setup.bash
.venv-vla/bin/python run_task_scene_preview.py \
  --task all \
  --checkpoint artifacts/smolvla_rgb_only_v13_recovery_goals/best \
  --output runs/rgb_only_manual_01 \
  --max-steps 200
```

出力先は存在しない新しい名前を指定する。録画を省略する場合は`--no-record`を追加する。
録画は各タスクの出力フォルダに保存される。深度動画は生成しない。

主な実装：

- `train_rgb_only.py`：RGBのみのSmolVLA追加学習。
- `train_rgb_temporal.py`：同じSmolVLAの特徴を使う学習可能な時系列出力層。
- `collect_rgb_only_corrections.py` / `collect_rgb_expert_recovery.py`：教師修正データの作成。
- `iss_capture/rgb_joint_policy.py`：入力の制限と関節目標の推論。
- `iss_capture/rgb_temporal_policy.py`：学習済み時系列出力層の推論。


## 開発評価結果

最新候補：`artifacts/smolvla_rgb_only_v13_recovery_goals/best`（検証損失で選択された出力層1,000ステップ）。
追加重みは約23.3MB。別途、既存のベースモデルが必要。
同じモデルインスタンス・同じ重みで、シード3300002の3タスクを各最大200ステップ実行した。

| タスク | 最新候補の結果 | 確認内容 |
|---|---|---|
| 水滴回収 | 成功 | 12ステップで右腕のスポンジに接触・接着 |
| ペン把持 | 失敗 | 200ステップ以内に安定把持を達成できず |
| キャップ装着 | 失敗 | 両物体は保持したが、挿入完了せず |

キャップの最終状態は挿入深さ-0.20mm、
横ずれ4.86mm、軸角度0.22度。
モデルが予測する動作段階が「保持」であっても、成功判定には採用していない。

初期候補 `artifacts/smolvla_rgb_only_v3_step1750_binary` では水滴・ペンの成功例があった
（`runs/rgb_only_dev_v3_binary_all/`）。ただし、後続の再試行ではペン把持が安定せず、
これを3タスク成功版や一般的な成功率として扱うことはできない。

最新の結果・動画：`runs/rgb_only_dev_v13_recorded/`。
各タスクのフォルダに `result.json`、`metrics.json`、4視点のMP4を保存。
一人称動画は `policy_front.mp4`、対面動画は `policy_opposite.mp4`。
深度センサー・深度ブリッジがゼロである記録は `depth_absence_audit.json`。
入力制限などの自動テストは22件成功。

**再学習とRGB限定の推論実装は完了したが、3タスクの成功という目標は未達。**
ペン把持の閉ループでのずれと、キャップ挿入直前の細かな位置合わせが残る。
改善候補は、失敗状態からの教師修正データの拡充と、作業領域のRGB解像度を上げた学習。
これらの効果は未確認である。
RGB版のソースコードは `rgb-only-smolvla` ブランチに分離する。
`main` は深度ありの実装・学習済みモデルを保持する。
RGB版の実験重み・追加データ・録画はローカルに保持し、このソースコードのコミットには含めない。
